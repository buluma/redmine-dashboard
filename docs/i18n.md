# Internationalization (i18n)

Converge supports multiple languages for its user interface, allowing global teams to use the application in their preferred language.

## Supported Languages

| Locale | Language | Region |
|--------|----------|--------|
| `en` | English | United States (default) |
| `es` | Spanish | Spain |
| `de` | German | Germany |
| `fr` | French | France |
| `ja` | Japanese | Japan |
| `zh` | Chinese | China |
| `ru` | Russian | Russia |
| `uk` | Ukrainian | Ukraine |
| `af` | Afrikaans | South Africa |
| `tl` | Tagalog/Filipino | Philippines |
| `pl` | Polish | Poland |
| `vi` | Vietnamese | Vietnam |

## Architecture

Converge uses a **client-side i18n approach** (no URL prefixes or server-side routing):

1. All 12 language files are loaded on app initialization
2. Locale is stored in `localStorage` (`converge-locale`)
3. Translation function is available via `useI18n()` hook
4. No page reload required when switching languages

## Usage in Components

### Using the `t()` Function

```tsx
"use client";

import { useI18n } from "@/src/components/I18nProvider";

export default function MyComponent() {
  const { t } = useI18n();

  return (
    <div>
      <h1>{t("dashboard.title")}</h1>
      <p>{t("common.loading")}</p>
      <button>{t("common.save")}</button>
    </div>
  );
}
```

### With Fallbacks

```tsx
// If the key doesn't exist, fall back to a default string
t("nonexistent.key", "Default fallback text");
```

### With Navigation

```tsx
// Use translation keys in navigation
<Link href="/dashboard">
  {t("nav.dashboard")}
</Link>
```

## Adding a New Language

### Step 1: Create the Translation File

1. Copy `messages/en.json` to `messages/{locale}.json`
2. Replace the content with translated strings

Example for Portuguese (`pt.json`):
```json
{
  "common": {
    "save": "Salvar",
    "cancel": "Cancelar",
    "delete": "Excluir"
  },
  "dashboard": {
    "title": "Painel",
    "openIssues": "Issues Abertos"
  }
}
```

### Step 2: Add Locale to the Loader

Update `src/components/I18nProvider.tsx`:

```tsx
const loadAllMessages = async () => {
  const locales = ["en", "es", "de", "fr", "ja", "zh", "ru", "uk", "af", "tl", "pl", "vi", "pt"]; // Add new locale
  for (const locale of locales) {
    try {
      translations[locale] = (await import(`../../messages/${locale}.json`)).default;
    } catch {
      translations[locale] = translations.en;
    }
  }
};
```

### Step 3: Add to Language Switcher

Update `src/components/LanguageSwitcher.tsx`:

```tsx
const languages = [
  { code: "en", name: "English" },
  { code: "es", name: "Español" },
  { code: "pt", name: "Português" }, // Add new language
  // ...
];
```

## Translation File Format

All translation files follow a **nested object structure**:

```json
{
  "common": {
    "loading": "Loading...",
    "save": "Save"
  },
  "dashboard": {
    "title": "Dashboard",
    "stats": {
      "open": "Open Issues",
      "closed": "Closed Issues"
    }
  },
  "nav": {
    "dashboard": "Dashboard",
    "groups": {
      "personal": "Personal",
      "teamOps": "Team Ops"
    }
  }
}
```

### Accessing Nested Keys

```tsx
const { t } = useI18n();

// Nested: common.loading
t("common.loading")

// Nested: dashboard.stats.open
t("dashboard.stats.open")
```

## Language Switcher

The language switcher is available in the sidebar navigation and displays:

- Current language code (e.g., "EN")
- Dropdown list of available languages
- Persists selection in `localStorage`

### Manual Locale Switching

```tsx
import { useI18n } from "@/src/components/I18nProvider";

export function LanguageSelector() {
  const { locale, setLocale } = useI18n();

  return (
    <select value={locale} onChange={(e) => setLocale(e.target.value)}>
      <option value="en">English</option>
      <option value="es">Español</option>
    </select>
  );
}
```

## Development Guidelines

### 1. Always Use Translation Keys

**Don't:**
```tsx
<h1>Dashboard</h1>  // Hardcoded string
```

**Do:**
```tsx
<h1>{t("dashboard.title")}</h1>  // Translation key
```

### 2. Keep Keys Consistent

Follow the existing structure:
- `common.*` - Shared UI elements
- `dashboard.*` - Dashboard-related text
- `nav.*` - Navigation labels
- `form.*` - Form labels and messages

### 3. Handle Missing Translations

The fallback system ensures keys always return text:
- If a translation is missing, it falls back to English
- If the key doesn't exist, it returns the key itself

### 4. Test New Translations

After adding translations:

1. Switch to the new language in the language switcher
2. Navigate through all pages
3. Verify all text is translated
4. Check for missing keys (they appear as `key.name`)

## Troubleshooting

### Translations Not Loading

1. Check browser console for import errors
2. Verify the JSON file exists in `messages/`
3. Ensure the locale is added to `I18nProvider.tsx`

### Language Not Persisting

1. Check browser console for `localStorage` errors
2. Verify cookies aren't blocking local storage
3. Try incognito mode to isolate issues

### Key Returns as Plain Text

If you see `some.key.name` instead of translated text:
- The translation file may be missing the key
- Add the key to the appropriate language file
- Or add a fallback: `t("some.key.name", "Default text")`
